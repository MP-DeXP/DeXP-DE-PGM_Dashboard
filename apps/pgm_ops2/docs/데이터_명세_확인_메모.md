# Rosetta MCP 데이터 명세 확인 메모

## source tables / fields / joins / time depth

- Revenue 주 source: `dma.silver_fact_product`
- 주문 canonical source: `core.silver_meta_order`, `core.silver_meta_order_item`
- UTM 보조 source: `dma.silver_order_with_utm`
- 브랜드 일별 요약: `dma.gold_purchase_analysis_daily`
- Role 주 source: `dma.gold_pgm_scored`, `dma.gold_pgm_product_demand_gravity`, `dma.gold_pgm_entry_to_expansion_transition`, `dma.gold_pgm_product_transition_edge`, `dma.gold_pgm_return_gravity_loop_detail`, `dma.gold_pgm_basket_gravity_detail`
- canonical join:
  - `order ↔ order_item` on `order_id`
  - `order ↔ member` on `member_id`
  - `order ↔ order_with_utm` on `order_id`
  - `product_daily/order_item/pgm_* ↔ product` on `product_id`
  - `silver_fact_product ↔ order_item` direct join 금지

## Revenue 가능한 정의

- 상품 일별 Revenue는 `dma.silver_fact_product`에서 직접 계산 가능
- 7/30/90일 rolling과 직전 동일 길이 window 비교는 파생 산출 가능
- 브랜드 수준 설명용 매출 컨텍스트는 `dma.gold_purchase_analysis_daily`를 보조로 사용 가능

## Role 가능한 정의

- `gold_pgm_scored` + `gold_pgm_product_demand_gravity` + transition/loop/basket detail 조합으로 상품별 role taxonomy 근거를 만들 수 있다.
- history는 짧으므로 `same-date snapshot only`를 원칙으로 잠근다.

## Brand Score 가능한 정의

- Entry / Expansion / Convergence / Return 4축은 Rosetta source만으로 고유사도 재현 가능
- Basket summary와 event intermediate는 직접 source가 부족해 재구성 로직이 필요하다.
- exact parity는 보장하지 않는다.

## unavailable / partial / confidence 규칙 초안

- source 최신일이 큐 기준일보다 뒤처지면 freshness 경고를 노출한다.
- 필수 축이 없으면 `unavailable`
- 산식은 가능하지만 intermediate 의미 차가 크면 `limited`
- 대부분 재현되지만 일부 입력이 재구성 기반이면 `provisional`
- 입력/축/산식이 core 정의와 매우 유사하면 `near-core`

## sample fixture와 real source 구분

- `apps/pgm_ops2/artifacts/raw_rosetta`는 Rosetta 실소스 snapshot 계층이다.
- fixture는 계약 테스트용으로만 허용하고, UI 기본 데이터로 승격하지 않는다.
